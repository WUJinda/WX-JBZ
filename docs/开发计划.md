## 0. 定位与现状

- 本计划把 PRD-P0（8 模块 F1~F8）与《技术架构设计》落地为**可执行任务清单**。
- 现状：PRD ✅、架构 ✅（v1.1.0）、开发计划 ✅（本文档）、代码 ❌（未开始）。
- 每个任务 = 一轮 `/loop-jbz`（builder 写 + checker 验，最多 5 轮内 PASS）。
- 任务表含**工期**（单人·日参考值）与**完成标准（checker 可验）**。

---

## 1. 前置约束

- **云环境未就绪** → 采用「本地轨 + 云轨」双轨：
  - **本地轨（先行）**：云函数以可部署 Node 包形态组织；**业务逻辑与微信 SDK 调用解耦**（纯函数可单测）；checker 主要跑单元测试 + 结构校验。
  - **云轨（环境就绪后）**：真实联调 `wxContext`/`code2Session`/解密/`getPhoneNumber`/定时触发器。
- 检查命令来源：`package.json` 的 scripts（test/lint/typecheck），checker 读 scripts 而非假设。
- 所有写操作经云函数，前端禁直写 DB；敏感字段（`phone`/`openid`）不下发前端。
- **身份以云运行时注入的 `OPENID` 为准，不再使用自管 token**（见架构 v1.1.0 §4.3）。

## 4. 每轮 loop-jbz 粒度约定

- **一个任务 = 一轮 loop**：任务名即任务简报，含「目标 / 涉及文件 / 完成标准」。
- 完成标准必须可被 checker 验证（单测 pass / 结构校验 pass / 接口契约符合）。
- 跨层改动（前端+云函数+表）优先按「数据层→云函数→前端」拆成相邻小任务，避免一轮改三层。
- 遇到非代码卡点（业务决策/外部依赖/环境），builder 走「举旗」，编排器提前交还用户。

## 5. 双轨 · checker 能跑的检查

- **本地轨**：
  - 业务逻辑单测（upsert 去重、脱敏、排名排序、异常阈值、频率计数、登录态/身份解析校验）。
  - 云函数结构（package.json/入口分发/action 路由）。
  - 前端结构（app.json 合法、页面注册完整、tabBar）。
- **云轨（环境就绪后追加）**：真实 code2Session、解密、getPhoneNumber、定时触发器端到端联调。
  - **强制项**：`auth.phone` 必须改为 `cloud.openapi.phonenumber.getPhoneNumber({code})` 解密取真实手机号，**禁止**信任前端明文 `event.phone`（否则白名单可被任意伪造手机号绕过）。本地轨明文透传仅为联调占位，上线前必须替换。

## 7. 排期建议（参考）

单人执行约 **6–7 周**（含联调缓冲）；双人并行关键路径约 **4 周**。总计约 **32 人·日**。

| 周 | 单人路线 | 双人路线（A=关键路径 / B=后台） |
|----|----------|--------------------------------|
| W1 | 阶段 A + B | A: 阶段A+B ／ B: 外部前置推进(T0-1)、H2 白名单导入 |
| W2 | 阶段 C+D+E | A: 阶段C+D+E ／ B: H1/H5 |
| W3 | 阶段 E 收尾 + F + G | A: 阶段F+G ／ B: H3/H4/H6/H7 |
| W4 | 阶段 G 收尾 + H | A: 阶段H 收尾 ／ B: G 协作 + 云轨回归 |
| W5 | H 收尾 + 云轨联调 | 双人合流：云轨端到端联调 |
| W6 | 上线缓冲 | 上线缓冲 |

> 微信审核周期（见 §9 的 1/2/5）不可控，**外部前置第一周必须启动**。

## 8. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| session_key 解密链路未验证就大干 | E2 返工 | 本地轨先用真实 encryptedData 样本验证"当次换 key"纯函数 |
| 微信权限/审核/类目未就绪 | 阻塞上线/云轨联调 | 外部前置第一周启动；权限项在开发者工具先验 |
| 定时任务本地无法调试 | 聚合/锁定 bug 拖到线上 | 暴露为手动 action（架构 §6.5），G2/G3 纯函数单测覆盖 |
| 白名单 xlsx 解析 | 导入功能不可用 | 云函数解析（`xlsx`/`csv-parse`），H2 前先验库 |
| 步数锁定口径引发排名争议 | 用户投诉 | 已定为次日 12:00 可配置（架构 §6.4 / PRD R3.4），运营确认时点 |
| 并发同步产生重复记录 | 排名虚高 | sync 用事务/先查后写保证唯一（架构 §5.5 / PRD R3.2），E2 单测验证 |
| 云环境延迟就绪 | 阻塞云轨 | 双轨策略：本地轨先行不阻塞，云轨作为收尾阶段 |
