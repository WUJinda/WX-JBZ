# /loop-jbz 停止规则

本文件由 `/loop-jbz` 编排器在每轮结束后对照执行。

所有跨轮判定都**读 `.claude/loop-state.json`**，不靠对话记忆——
上下文总结不会冲掉磁盘文件。

## 失败指纹

每轮 checker 的失败项按下式归一化为「指纹」，用于跨轮比对：

  指纹 = "<file>:<line> <检查项>"

例：`src/auth.ts:42 lint`、`src/auth.ts:42 test` 视为两条不同指纹
（同位置不同检查）。一轮的失败指纹组成一个**集合**。

## 最大轮数
- 默认 **最多 5 轮** builder↔checker 循环。
- 达到最大轮数仍未 PASS → **强制停止**，按「失败收尾」处理。

## 成功停止
- checker 输出 `VERDICT: PASS` → 立即成功结束，不再进入下一轮。

## 死锁停止（拉锯检测）
- 若 checker 连续 **2 轮**的失败指纹集合**实质相同**（集合相等，或本轮
  指纹是上一轮的子集且无新指纹），判定为拉锯——builder 的修复未真正
  消除同一问题，可能在瞎猜 → **停止**。
  - **判定方法是集合比对，不是解读单轮失败**——这不违反编排器
    「原样转发、不解读」的纪律。
  - 交还用户：报告卡点、checker 的失败项、builder 最后一轮的改动，
    请用户介入。

## 打地鼠停止（越改越烂检测）
- 若 checker 连续 **3 轮** FAIL，且每轮的失败指纹集合**两两几乎无交集**
  （builder 每轮都在引入新问题，而不是收敛），判定为打地鼠 → **停止**。
  - 这与拉锯相反：拉锯是「老问题不动」，打地鼠是「老问题没了但新问题
    不断冒」。两者都说明循环已失控。
  - 交还用户：报告最近几轮的失败项变化趋势，请用户介入。

## 回归停止（拆东墙补西墙）
- 若某项检查**上一轮在通过项清单里、本轮出现在失败项里** → **停止**。
  - 判定依据：checker 每轮报告里的「通过项清单」与失败项，跨轮比对。
    没有通过项清单就无法做回归检测——所以 checker 在 FAIL 时也必须
    列出通过项。
  - 这通常意味着修复引入了新问题，或在各检查间来回拆补；继续循环
    只会震荡。
  - 交还用户：报告哪个原本通过的检查挂了、builder 本轮改了什么。

## builder 举旗停止
- builder 汇报了 🚩 举旗（非代码层面的卡点）→ **立即停止**，把卡点
  原样交还用户，不进入下一轮。

## 用户中止
- 用户随时可中断。中断后保留已完成轮次的改动与最后一轮 checker 结论。

## 失败收尾要求
停止时若仍 FAIL，必须如实向用户报告：
1. 已执行的轮数。
2. checker 最后一次的 VERDICT 与失败项。
3. 当前代码处于什么状态（可编译 / 部分实现 / 有已知缺陷）。
4. 触发的是哪条停止规则（最大轮数 / 死锁 / 打地鼠 / 回归 / 举旗）。

**不得隐瞒未解决的问题，不得谎报成功。**
